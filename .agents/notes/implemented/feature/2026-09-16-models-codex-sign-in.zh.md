# Agent Note: 从模型设置登录 Codex

Status: implemented

[English](2026-09-16-models-codex-sign-in.md) | 中文

## 问题

已安装的 pi-ai 目录提供 Codex 模型，其授权适配器也注册了登录流程，但模型页无法启动该流程或展示通知。未指定凭据引用的路由还可能在没有账号凭据时显示为就绪。

## 决策

设置控制器将现有授权服务投射到调用方私有的 Remote 流。只有发起登录的卡片收到授权 URL、设备码和输入问题。问题回复使用每次尝试独有的凭证。关闭卡片会取消该次尝试；提供方撤销手动输入码的问题时，不会取消仍在等待的浏览器回调。已存储令牌保留在现有凭据提供方中，协议与刷新仍由 pi-ai 负责。

内置 Codex 编辑器通过 localhost 提供账号控件，并根据已存储授权的元数据判断就绪状态。Host 方法保留现有配置传输的认证及 Host/Origin 策略。显式 API 凭据引用仍然优先，并作为覆盖配置显示，不会被静默丢弃。

## 考虑过的替代方案

**在 Web 插件中重新实现 OAuth。** 未采用，因为已安装的 pi-ai 适配器已经负责登录、凭据存储集成与刷新。

**通过全局事件广播登录通知。** 未采用，因为其他浏览器不应收到发起用户的授权 URL 或设备码。

**读取 Codex CLI 凭据文件。** 未采用，因为本功能需要 Harness 独立管理凭据，无需与另一应用共享轮换令牌。

## 影响

现有提供方配置和凭据格式保持不变。用户显式打开授权链接，因此浏览器拦截弹窗不会隐藏登录提示。账号登录和提供方配置是两个独立操作：登录后点击应用保存路由。卡片断开或关闭后，重试会启动新的尝试。真实账号授权仍需要用户完成提供方的同意流程。
